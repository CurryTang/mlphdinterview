### 1. 工业 ML 与学术 ML 的根本差异

- **学术 / 离线 ML**：在静态、固定的测试集上最大化预测准确率或拟合度。
- **工业 / 线上 ML**：与动态环境交互，追求**核心业务指标的因果增量（Causal Increment / Uplift）**与**长期生态健康度（如 DAU、GMV、留存率、算力 ROI）**。

### 2. “离线涨点，线上平甚至跌点”的四大根因

1. **反馈闭环与自选择偏差（Feedback Loops & Selection Bias）**：
   离线训练数据是由旧策略曝光产生的数据（Log Data）。新模型推荐的高潜新内容在离线测试集中可能根本没有用户交互记录，导致被判定为“负例”；
2. **特征分布漂移与特征穿越（Training-Serving Skew & Leakage）**：
   离线使用了“未来特征”或未严格对齐时间戳，而线上推理时特征服务存在毫秒级延迟或部分实时特征缺失；
3. **系统时延与 P99 降级损耗（System Latency & Degradation）**：
   离线更复杂的模型（如更大参数量、更多交叉层）虽然指标稍高，但导致线上 P99 延迟增加 50ms，触发了超时截断降级规则，且用户等待时间变长直接导致跳出率上升；
4. **多目标冲突与局部最优（Multi-Objective Conflict）**：
   单目标模型（如单纯优化点击率 CTR）可能诱发标题党和诱导点击，导致用户进入落地页后秒退，反向摧毁了最终转化率（CVR）和长期留存。

## 模块二：工业级 A/B 实验全生命周期流水线

### 1. 核心统计学指标与因果推断基础

- **原假设 ($)** 与 **备择假设 ($)**：
  - : \mu_{	ext{treatment}} - \mu_{	ext{control}} \le 0$（新策略无正向增益）
  - : \mu_{	ext{treatment}} - \mu_{	ext{control}} > 0$（新策略带来统计显著正向增益）
- **第一类错误率 ($lpha$, False Positive Rate)**：通常设为 zsh.05$（即有 \%$ 的概率在 $ 为真时错误地拒绝原假设）。
- **第二类错误率 ($eta$, False Negative Rate)** 与 **统计功效 ($	ext{Power} = 1 - eta$)**：通常要求 Power $\ge 80\%$（即当新策略确实有效时，有 \%$ 的概率成功检测出显著差异）。
- **最小可检测效应（MDE, Minimum Detectable Effect）**：在给定 $lpha, eta$ 和样本方差下，实验能够可靠检测到的最小相对/绝对指标提升幅度。

```text
                                    │ 流量正交穿透 (Orthogonal)
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ Layer 2: 精排与多目标层 (Ranking Layer) ➔ Hash(user_id, salt_2)        │
│ [ 对照组: 旧精排 (50%) ]              [ 实验组: 新精排 (50%) ]          │
└───────────────────────────────────┬────────────────────────────────────┘
                                    │ 流量正交穿透 (Orthogonal)
                                    ▼
┌────────────────────────────────────────────────────────────────────────┐
│ Layer 3: UI 界面与交互层 (UI/UX Layer) ➔ Hash(user_id, salt_3)         │
│ [ 对照组: 红色顶部按钮 (50%) ]         [ 实验组: 蓝色底部按钮 (50%) ]    │
└────────────────────────────────────────────────────────────────────────┘
```

- **同层互斥**：相同功能模块的两个替代算法（如两套召回模型）必须在同一层内互斥分流，避免单个用户同时被两个竞争算法干扰；
- **跨层正交**：不同功能层（如召回层与 UI 界面层）使用不同的哈希加盐（Salt），使流量均匀打散。跨层用户交集处于随机正交分布，大幅提高平台多实验并发吞吐量。

### 1. 假设体系、实验分组、随机化单元与核心指标

#### (1) 业务与统计假设（Hypotheses）
- **原假设 ($)**：改变按钮颜色、改变按钮位置或同时改变两者，对注册页面的点击转化率无显著正向影响（$\mu_T \le \mu_C$）。
- **备择假设 ($)**：
  - **颜色主效应假设 ({1,	ext{color}}$)**：蓝色按钮相比红色按钮能显著提升 CTR（因蓝色在心理学上更具合规感与专业度）；
  - **位置主效应假设 ({1,	ext{position}}$)**：底部按钮相比顶部按钮能显著提升 CTR（因用户在浏览完产品特性与价值宣讲后，位于底部的行动点更符合 F 型阅读决策动线）；
  - **交互效应假设 ({1,	ext{interaction}}$)**：颜色与位置同时改变会产生显著的协同（Synergistic）或拮抗（Antagonistic）增益。

#### (2) 对照组与实验组设计（Control & Treatment Conditions）
采用 ** 	imes 2$ 全因子设计（Full Factorial Design）**，将流量等分为 4 个独立分组：
- **对照组 ($, Control)**：红色 + 顶部（现状基线，Red + Top）；
- **实验组 1 ($, Treatment 1)**：蓝色 + 顶部（单改颜色，Blue + Top）；
- **实验组 2 ($, Treatment 2)**：红色 + 底部（单改位置，Red + Bottom）；
- **实验组 3 ($, Treatment 3)**：蓝色 + 底部（双重改动组合，Blue + Bottom）。

#### (3) 随机化单元（Randomization Unit）
- **推荐选择**：**未登录匿名访客的持久化设备 ID（Persistent Device ID / Cookie ID）**。
- **选型原因**：注册漏斗页面的主要访客均为未注册新用户，尚未拥有 `user_id`。
- **关键要求**：必须在客户端与服务端保证分流 Hash 稳定性（`hash(device_id, exp_salt) % 4`），**严禁使用 Session ID 或 Request ID 作为随机化单元**。如果用户刷新页面或发生跳转时按钮忽红忽蓝、忽上忽下，不仅会造成极差的用户体验，还会破坏 SUTVA（个体间处理稳定性）假设导致实验失效。

### 3. 如何严密评估按钮颜色与位置的交互效应？

#### (1) 交互效应线性回归与方差分析模型（Two-Way ANOVA / OLS）
我们对每个用户 $ 建立线性概率模型（Linear Probability Model）或 Logistic 回归：

36589Y_i = eta_0 + eta_1 \cdot 	ext{Blue}_i + eta_2 \cdot 	ext{Bottom}_i + eta_3 \cdot (	ext{Blue}_i 	imes 	ext{Bottom}_i) + \epsilon_i36589

其中：
- $	ext{Blue}_i \in \{0, 1\}$（蓝色为 1，红色为 0）；
- $	ext{Bottom}_i \in \{0, 1\}$（底部为 1，顶部为 0）；
- $eta_1$：颜色在顶部的**边际主效应**（$\mathbb{E}[T_1 - T_0]$）；
- $eta_2$：位置在红色的**边际主效应**（$\mathbb{E}[T_2 - T_0]$）；
- $eta_3$：**交互效应系数（Interaction Effect）**。

#### (2) 交互效应系数 $eta_3$ 的定量计算与假设检验

36589\hat{eta}_3 = (ar{Y}_{T_3} - ar{Y}_{T_1}) - (ar{Y}_{T_2} - ar{Y}_{T_0}) = ar{Y}_{T_3} - ar{Y}_{T_2} - ar{Y}_{T_1} + ar{Y}_{T_0}36589

我们对 : eta_3 = 0$ 进行双侧 Wald 检验或 t 检验：
- 若 **$eta_3 > 0$ 且统计显著 ( < 0.05$)**：存在**超额协同效应（Synergistic / Super-additive）**。说明蓝色按钮在底部呈现时，视觉焦点与操作动线发生了强烈的共振增益（ + 1 > 2$），组合方案 $ 为最优解；
- 若 **$eta_3 < 0$ 且统计显著 ( < 0.05$)**：存在**负向拮抗效应（Antagonistic / Sub-additive）**。说明虽然改颜色有效、改位置也有效，但两者叠加后相互稀释或视觉过度突兀引起用户警惕（ + 1 < 2$）；
- 若 **$eta_3 pprox 0$ 且不显著**：说明颜色与位置相互独立，效应完全线性可加（Additive）。

### 4. 准入准出条件、触发曝光、监控周期、样本量估算与决策准则

#### (1) 准入条件（Eligibility Criteria）
- **纳入范围**：所有通过有效渠道进入注册着陆页的**新访客设备**；
- **排除范围**：内部员工 IP、爬虫与搜索引擎 Bot 流量、以及不支持该 CSS 布局的古董浏览器客户端。

#### (2) 触发曝光定义（Triggered Exposure Definition）—— 关键防稀释机制
- **工业界重大陷阱**：严禁在“页面 HTML 发起请求时”就将用户计入实验分母！
- **正确曝光日志（Triggered Impression）**：
  - 对于顶部按钮：首屏渲染完成即可记录曝光；
  - **对于底部按钮**：必须当用户实际**向下滚动页面、且按钮真正进入浏览器可视视口（Viewport Intersection Observer 触发）**时，才记录该用户的有效曝光事件！
  - **如果不做视口曝光触发**：大量只看首屏就离开的用户会被错误计入底部按钮的分母中，导致底部按钮的真实效果被严重稀释（Dilution Bias）。

### 5. 下游全链路指标、护栏指标与生态蚕食效应

   - **技术性能**：页面加载耗时（Page Load Time）、P99 首屏渲染时延、JS 异常报错率；
   - **用户体验**：注册页跳出率（Bounce Rate）、会话平均停留时长。
3. **旁路功能蚕食分析（Cannibalization Analysis）**：
   - 着陆页上通常还有其他重要导流链接（如 `"已有账号登录 (Log In)"`、`"了解企业方案 (Enterprise Pricing)"`、`"联系客服"`）；
   - **蚕食度评估**：检查新注册按钮是否过度占据视觉中心，导致高客单价的“企业咨询”或已有用户的“正常登录”点击量发生显著下降。

## 模块四：工业级 A/B 实验核心自测题

### Q1：为什么在 A/B 测试中，即使第 3 天 p-value 已经达到了 0.001，也坚决不能提前关停并宣布胜利（Peeking Problem）？
> **答**：
> 1. **多重假设检验假阳性膨胀（Alpha Inflation via Continuous Monitoring）**：传统的假设检验假设样本量是固定的。如果在实验运行期间每天甚至每小时去“偷看（Peek）”数据并在显著时立即早停，本质上是在进行数十次重复假设检验。真实的全局第一类错误率（False Positive Rate）会从 \%$ 迅速飙升至 \%\sim40\%$；
> 2. **周期性偏差（Day-of-Week Seasonality）**：工作日与周末的用户画像、决策耐心存在显著周期性波动，未跑满完整周周期（如 14 天）的样本无法代表长期稳态；
> 3. **新奇效应尚未消退**：早期显著往往由用户的新奇感引起，随着时间推移效应可能衰减归零甚至反转。若确需动态早停，必须采用严格的 **Sequential Testing 序列检验（如 mSPRT / Alpha-Spending Function）** 调整拒绝域阈值。
